# Phone welcome and bottom navigation

The phone navbar is fixed to the bottom, with five icons and visible labels: Home, Work, Skills, About and Contact. It appears at widths up to 800px, or up to 1100px with a coarse pointer so landscape phones retain it. The original desktop navigation remains; on phones the wordmark stays at the top and scrolls normally.

`index.html` contains native anchors and decorative SVG icons, plus `viewport-fit=cover`. `assets/css/site.css` styles the bar in both themes and reserves page-bottom space, including safe-area insets. Links have at least 44px touch targets and visible keyboard focus. `assets/js/mobile-navigation.js` updates `aria-current="location"` as sections scroll into view, with updates batched per animation frame. Contact reuses the existing keyboard-aware navigation in `scroll-navigation.js`. Without JavaScript the bar and anchors still work.

The critical-CSS generator includes the bottom-bar styles so it does not appear late or flash at the top. Run `node scripts/build-critical-styles.mjs` after CSS edits. Changed stylesheet and script entry URLs have updated cache versions. The [mobile welcome](loading-screen.md) lasts five seconds and finishes with the original animated Namaste.

Verification on 2026-11-09: all **119 Node tests passed**; Lighthouse accessibility was **100/100**, with no failed automatic audits. Browser checks passed at 320, 390, 430 and 800px, plus an 844 × 390 landscape phone. Touch targets measured 57px high, with no horizontal overflow. The bar stayed at the viewport bottom; Contact navigated and focused its heading. Light/dark themes, desktop layout, reduced-motion bypass and no-JavaScript fallback passed. The welcome measured 5001ms and displayed all greetings in order. This is local browser verification, not a production deployment or LCP measurement. Evidence is in `docs/performance/mobile-welcome-2026-11-09.json`.
