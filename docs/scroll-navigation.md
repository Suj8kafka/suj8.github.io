`assets/js/scroll-navigation.js` handles the header's detached state and both enhanced anchors: “Let's talk” and “Back to top.” Each click makes one native `scrollIntoView` request. It does not calculate or write scroll positions in an animation loop, and real anchor links still work without JavaScript.

Both scroll directions use a fixed viewport overlay with 2 px backdrop blur and softly feathered top/bottom edges. It covers the visible page instead of a narrow band. Opacity follows native scroll speed up to 95%, with a square-root response so moderate speeds still show the effect, and fades out in 160 ms on arrival or interruption. The overlay is hidden after fading so its backdrop is not rendered while idle. Only opacity changes per frame; the blur radius stays fixed and no document-height filter is created. Parallax freezes during these trips and resumes on arrival or cancellation. Header layout transitions and header backdrop filtering are suspended during the trip.

Touch/compact screens, data saving, and devices reporting at most 4 GB memory or four logical cores use lighter 1.2 px blur rather than hiding the effect. Repeatedly late scroll frames also select this lighter mode. Light and reduced-motion modes use an opaque header surface rather than header backdrop filtering. Reduced motion is the only preference that disables the scroll blur and requests an instant jump; normal smooth scrolling remains native in both blur modes.

Scroll completion uses `scrollend` with an idle debounce fallback and a hard cleanup timeout. Wheel, touch, pointer and navigation-key input interrupt an active trip immediately. Repeated clicks replace the existing trip. Keyboard activation focuses the destination heading without scrolling again; pointer activation does not move focus. Contact's CSS scroll margin accounts for the fixed navigation.
