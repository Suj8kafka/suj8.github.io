Usage analytics, open to everyone

This portfolio uses a small analytics service built on Cloudflare Workers and D1. When connected, it counts page loads, sections reached, and clicks on projects, articles, CV, email, social and notebook links, skill details and theme choices. A click count shows intent; it does not confirm that a download finished or an email was sent.

It also measures estimated active time per page and section, and whether the portfolio reached 25%, 50%, 75% or the bottom of its scrollable distance. Time is counted while the page is visible and focused, pauses after 60 seconds without input or scrolling, and skips long browser-suspension gaps. It starts after the welcome overlay closes. This estimates foreground activity rather than attention or actual reading.

Time is sent in small batches, approximately every 15 seconds and on tab changes or departure, and added to daily counters. Only elapsed milliseconds and fixed section labels are included. Input events refresh an inactivity timer without recording keys, text or pointer coordinates in these analytics. One page load is limited to one hour of estimated active time and 240 timing reports. Closing a browser can prevent the last report from arriving.

Page loads are grouped by public page, referral source, browser family, device type and approximate country. Referral sources are stored as broad categories such as Google or LinkedIn; unrecognised sites are grouped as “Other websites”. URL queries, campaign tags, fragments and referral paths are not stored.

The service immediately adds to daily counters. It does not store individual event histories, raw IP addresses, full browser identifiers, names, email addresses, form contents or persistent visitor IDs in the analytics database. Counts are public on this page. It does not record sessions, screenshots or keystrokes.

This usage tracker sets no cookies and uses no browser storage. It respects Do Not Track and Global Privacy Control signals. Those signals apply to the usage tracker; essential hosting, security processing and the separate live presence feature still operate.

Live presence, cursors & location

The portfolio’s live studio uses Firebase anonymous sign-in with an identity held in memory for each page. It shares a temporary visitor label, current section and path, approximate country, activity time and, when enabled, section-relative cursor coordinates with other connected visitors. This is separate from the daily usage counters above.

An approximate country lookup sends a request to ipwho.is, which receives your network address. Selecting “Use my precise location” asks for browser permission and sends your coordinates to BigDataCloud to resolve a city or locality. The site shares the resulting location label in live presence; it does not save the coordinates in Firebase.

You can turn cursor sharing and display off in the live studio panel. Reduced-motion settings also disable cursors. Precise location is optional and can be revoked in your browser settings. Presence records are scheduled for removal when a connection closes; stale records are hidden after about two minutes. Disconnection and cleanup can be delayed.

What stays in your browser

Your colour theme is saved locally so the site can remember Light, Dark or Auto. The welcome animation stores a seen flag in local and session storage so it does not repeat unnecessarily. These preferences are separate from analytics and can be removed by clearing this site’s browser data.

The owner’s login page uses Firebase authentication to manage availability. Login credentials and owner access are not part of this public analytics dashboard.

Services, security & retention

GitHub Pages hosts the portfolio. Cloudflare handles edge delivery, security and aggregate traffic estimates. Firebase handles live presence and availability. These providers receive the network information needed to serve requests and operate under their own policies. The site’s analytics database does not store raw IP addresses; infrastructure providers may process them for delivery and security.

Daily usage counters are retained for up to 90 UTC calendar days, with a scheduled daily cleanup. The dashboard offers today, seven-day and thirty-day views. The older Firebase country counter is a separate cumulative count with no automatic expiry. Cloudflare traffic-history retention is managed separately by Cloudflare.

This portfolio does not sell visitor data or use these counters for advertising profiles. Links to external projects, social networks and the blog take you to services with their own privacy practices.
